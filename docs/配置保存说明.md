# 配置保存说明

本文说明发运主体定义与发运预设的保存位置、写入机制和常见问题。

## 一、涉及的文件

| 文件 | 内容格式 |
|------|----------|
| `config/entity_definition.json` | 发运主体定义：`[[代码, 名称, 说明], ...]` |
| `config/shipping_presets.json` | 预设：`{"presets": {...}, "current_preset": "..."}` |

仓库里的这两份文件同时充当"出厂默认配置"，打包时会被打进 EXE。

## 二、保存位置

配置目录由 `utils/helpers.py` 的 `get_writable_app_dir()` 决定：

| 运行方式 | 配置目录 |
|----------|----------|
| 开发环境 `python main.py` | 项目根目录下的 `config/` |
| 打包后的 EXE | **EXE 所在目录下的 `config/`**（如 `dist/config/`） |

首次运行 EXE 时，程序会把包内的出厂配置播种到可写目录：

- 只复制**目标文件不存在**的配置，不覆盖用户已修改的文件
- 位于 `core/entity_config.py` 的 `__init__`，调用 `seed_file_from_bundle()`

因此升级 EXE 时，只要保留原 `config/` 目录，用户配置不会丢失。

## 三、保存入口

界面入口：**发运主体定义** 对话框（可编辑定义、管理预设）。

调用链：

```
ui/entity_mixin.py
  └─ EntityConfigManager.save_definitions(entities)   # 保存定义
  └─ EntityConfigManager.save_presets(config)         # 保存预设 / 切换当前预设
       └─ core/entity_config.py
```

两个方法都返回 `bool`：

- `True`：写入磁盘成功
- `False`：写入失败，原因记录在 `last_error`，界面会弹窗显示真实错误

不要在调用方忽略返回值，否则会出现"提示保存成功、重开后配置丢失"的假成功。

## 四、写入机制

采用**临时文件 + 原子替换**，避免写入中断留下半截 JSON：

```python
tmp_file = 正式文件.with_name(正式文件.name + '.tmp')
with open(tmp_file, 'w', encoding='utf-8') as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
os.replace(tmp_file, 正式文件)
```

特点：

- UTF-8 编码，`ensure_ascii=False` 保留中文原文
- `os.replace` 在 Windows 上是原子操作，读方不会读到写了一半的文件
- 写入失败会清理临时文件不彻底（极端情况下残留 `.tmp`，不影响正式文件读取）

## 五、读取失败与损坏处理

当 JSON 损坏、编码异常（如带 BOM）或结构不正确时：

1. 自动备份为 `.corrupt.<时间戳>.bak`（毫秒级时间戳，避免同秒覆盖）
2. 原因记录到 `last_load_error`，界面提示用户
3. 本次使用内置默认配置
4. **不会静默用默认值覆盖原文件**；只有用户主动保存才会写回

这样可以避免"配置文件损坏 → 程序显示默认值 → 用户保存 → 原配置被永久覆盖"。

## 六、常见问题

### 1. 保存提示失败，配置没有写入

最常见原因是 **EXE 放在不可写目录**（如 `C:\Program Files`）。配置写入 EXE 所在目录，请把程序放到桌面、D 盘或 `dist/` 等可写位置。

### 2. 配置文件和"工作进度"不是一回事

| 数据 | 保存位置 | 保存方式 |
|------|----------|----------|
| 发运主体定义、预设 | `config/*.json` | 发运主体定义对话框中保存 |
| 当前项目的 BOM、发运配置、进度 | `.xlsx`（默认 `progress/`） | 工具栏"保存进度" |

### 3. 多开程序同时保存

临时文件名固定为 `<正式文件>.tmp`，两个实例同时保存时可能互相覆盖。建议同一时间只运行一个程序实例。

### 4. 手动编辑配置文件

可以直接用文本编辑器修改 JSON，但必须保证：

- UTF-8 编码（不建议带 BOM）
- 定义文件顶层是 `[[代码, 名称, 说明], ...]` 列表
- 预设文件顶层是含 `presets` 字典的对象

结构不正确时程序会备份原文件并回退默认配置。

## 七、相关代码

- `core/entity_config.py`：配置读写、原子写入、损坏备份、出厂播种
- `utils/helpers.py`：`get_writable_app_dir()` / `get_bundle_dir()` / `seed_file_from_bundle()`
- `ui/entity_mixin.py`：配置对话框与保存调用
